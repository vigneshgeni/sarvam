How every screen adapts to the document.

One design system, many documents. The API fields decide which blocks appear; empty fields hide their block. Never show sample text.

7 · ONE UPLOAD, SEVERAL DOCUMENTS OR SECTIONS (screen 3f)
Lab report → D valuesRx → medicinesBill → F
Split: when the pages hold more than one document (new issuer, new letterhead, new title), the API returns parts[], each with its pages, type, issuer and date. One part: the normal single result. Each part keeps its own layout: lab report → value tiles (D), prescription → medicine cards, bill or statement → amount strip (F), notice → deadline (C). Parts appear in page order under "Document N of M · pages". Sections inside a lab report use the report's own headings (Blood sugar, Lipid profile…). Sections with a printed High/Low flag come first, open; all-in-range sections are collapsed with an "All in range" pill. Look at these first lists every flagged value across sections, at most 6, each linking to its section. Hidden when nothing is flagged. What you need to do merges actions from all parts, each with a "From: …" tag. Key facts show which part and page each fact came from.
